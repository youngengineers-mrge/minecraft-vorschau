Was soll entstehen?

Der Spieler stellt einen vierstelligen Binärcode ein. Die Prüfung erfolgt nicht laufend, sondern erst, wenn der Spieler auf den Taster drückt. Dafür nutzen wir zunächst einen Impuls-Befehlsblock. Die eigentliche Codeprüfung übernimmt unsere vorhandene Datapack-Funktion young:pruefen_zaehler.

Voraussetzung: Projekt 3 funktioniert bereits. Das Scoreboard richtige ist angelegt; die Funktion young:pruefen_zaehler prüft die vier gespeicherten Werte und ruft bei vier Treffern young:code_richtig auf.

Schritt 1 – Welt vorbereiten

  1. Öffne deine Testwelt im Kreativmodus mit aktivierten Befehlen.
  2. Kontrolliere im Chat mit /function young:start, dass die vier Testwerte gesetzt werden.
  3. Prüfe mit /function young:pruefen_zaehler, ob die bisherige Codeprüfung funktioniert.
  4. Mit /scoreboard players get @s richtige kannst du den aktuellen Trefferzähler prüfen.

Benutze für diesen Aufbau eine freie Stelle. Du musst die Weltdateien nicht verändern.

Schritt 2 – Befehlsblock beschaffen

Gib im Chat ein:

/give @s minecraft:command_block

Öffne dein Inventar, lege den erhaltenen Befehlsblock in die Schnellzugriffsleiste und platziere ihn auf dem Boden.

Bringe einen Steintaster direkt an einer Seitenfläche des Befehlsblocks an. Er soll den Block beim Drücken mit Redstone versorgen.

Schritt 3 – Befehlsblock einstellen

  1. Öffne den Befehlsblock mit Rechtsklick.
  2. Stelle ihn auf Impuls (nicht „Wiederholen“).
  3. Wähle Unbedingt.
  4. Wähle Benötigt Redstone.
  5. Schreibe in das Befehlsfeld ohne führenden Schrägstrich:
execute as @p run function young:pruefen_zaehler

Bestätige die Eingabe. @p wählt den dem Befehlsblock nächstgelegenen Spieler. Durch execute as @p wird die Funktion im Namen dieses Spielers ausgeführt: @s richtige bezeichnet anschließend dessen persönlichen Zähler.

Wichtig: Teste allein unmittelbar neben dem Befehlsblock. Bei mehreren Spielern könnte @p einen anderen, näher stehenden Spieler auswählen. Später entwickeln wir eine eindeutige Zuordnung.

Schritt 4 – Den ersten Test durchführen

  1. Stelle zunächst den richtigen Code in den gespeicherten Schalterwerten ein: Starte dazu /function young:start (im ursprünglichen Projekt ist das 1010).
  2. Drücke den Taster am Befehlsblock einmal.
  3. Öffne den Chat. Erwartet: „Code erkannt!“.
  4. Prüfe den Zähler mit /scoreboard players get @s richtige. Erwartet: 4.

Falls du Projekt 3 bereits auf den Code 1001 umgestellt hast, gilt natürlich der Code deiner start.mcfunction und der vier Bedingungen in pruefen_zaehler.mcfunction.

Schritt 5 – Mit einem falschen Code testen

Verändere genau einen gespeicherten Schalterwert; beim ursprünglichen Code 1010 zum Beispiel:

/scoreboard players set #s3 young_code 0

Drücke den Taster erneut und gib dann ein:

/scoreboard players get @s richtige

Erwartet: 3. Die Erfolgsmeldung darf diesmal nicht erscheinen. Wenn du danach die Funktion young:start erneut aufrufst, wird der richtige Code wiederhergestellt.

Was haben wir gelernt?

Der Taster löst genau beim Drücken eine Prüfung aus. Der Befehlsblock ruft nur die Datapack-Funktion auf; die vier Bedingungen bleiben in der Datei pruefen_zaehler.mcfunction. So trennen wir Eingabe, Auslösung und Auswertung.

Wichtig: Unsere vier Schalterwerte sind in dieser ersten Erweiterung noch gespeicherte Zahlen. Die echte Abfrage von vier gebauten Hebeln ist ein weiterer Schritt. Ein Taster allein liest noch keine Hebel aus!

Zusatzversuch – Trittplatte

Entferne den Taster und setze eine Steindruckplatte oben auf einen Befehlsblock oder stelle eine Redstone-Verbindung zwischen Platte und Befehlsblock her. Wenn du die Platte betrittst, aktiviert sie den Impuls-Befehlsblock. Vergleiche: Wann lässt sich der Taster leichter kontrollieren? Bei einer Trittplatte kann auch das Betreten durch andere Spieler oder bestimmte Entities eine Auslösung verursachen.

Eine Trittplatte auf einem Befehlsblock kann je nach Platzierung der Umgebung schwer zugänglich sein. Nutze in einer größeren Anlage lieber eine kurze Redstone-Leitung und platziere den Befehlsblock geschützt.

Kontrollliste

  • ☐ Der Befehlsblock reagiert genau auf den Tastendruck.
  • ☐ Richtiger Code: Erfolgsmeldung und Zähler = 4.
  • ☐ Ein falscher Schalter: keine Erfolgsmeldung und Zähler = 3.
  • ☐ Der Zähler wächst bei wiederholten Tastendrücken nicht über 4.
  • ☐ Ich kann erklären, warum execute as @p verwendet wird.

Ausblick

Als Nächstes können wir vier echte Hebel auslesen und die Codeprüfung vollständig in der Welt ausführen. Eine weitere Stufe wäre die Ereigniserkennung mit einer Datapack-Tick-Funktion, damit der Befehlsblock entfällt.
